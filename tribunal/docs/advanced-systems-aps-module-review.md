## Stable Eden and Zeus activation contracts

A genuine typed Eden module installs APS on every exact valid synchronized vehicle; multiple modules aggregate. The non-disposable native module and Sync relations remain available. A genuine module placed by an assigned curator activates exactly one selected vehicle once. The server validates module identity, requester, target, current transition, and replay; returns a correlated truthful result only to the placing curator; and consumes only its own disposable logic. Invalid, ambiguous, unauthorized, stale, or replayed requests change no vehicle/resource and delete no unrelated object.

## Canonical twelve-question review

1. **User or integrator observation.** Mission makers synchronize vehicles to
   the Eden module to install APS at mission start. An authorized curator places
   the Zeus module on one vehicle to toggle APS. The observation is authentic
   activation of accepted APS behavior, not another APS implementation.
2. **Current behavior and negative paths.** Native Eden dispatch executes on the server with local owner-2 logic and `remoteExecutedOwner=0`. For Zeus, the placing client observes native `CuratorObjectPlaced`, submits one exact operation claim, and the configured server handler waits boundedly for that claim. The server requires one exact vehicle candidate and consumes the claim before activating and deleting only the typed disposable logic.
3. **Authority, locality, and lifecycle.** Eden mutation is server-owned and validates exact class, server locality/owner, and native dispatch. Zeus derives the requester from `remoteExecutedOwner`, requires the exact requester-owned typed logic, assigned curator, server curator-editable target, and one matching attached/synchronized vehicle. Replay IDs are retained for five minutes in a 128-entry bounded cache; consumed claims retire immediately. Accepted feedback is remote-targeted only to the placing owner. Client-B nonrecipient isolation remains environment-deferred.
4. **Generic mechanics.** Typed mission-module generation, native SQM Sync
   links, configured-function receipts, execution locality, real curator
   placement, and exact logic cleanup can be product-neutral Tribunal mechanics.
   APS state and combat meaning remain Advanced Systems.
5. **Product-owned behavior.** Advanced Systems owns valid vehicles, aggregate Eden-module behavior, APS installation side effects, authorized curators, exactly-one Zeus selection, placing-curator feedback, and disposable Zeus logic cleanup.
6. **Engine facts.** For this Eden class, `isGlobal=0` configured dispatch ran server-local with owner 2 and `remoteExecutedOwner=0`; non-server forwarding was unnecessary. Native mission Sync links were visible on server and client-a. For native curator placement, the logic is local on the placing client while the server observes its owner as that client; the configured handler cannot recover the placer from ambient `remoteExecutedOwner`, so `CuratorObjectPlaced` supplies the authenticated claim. `curatorMouseOver` reports `["OBJECT", object]`. 7. **Fragile or incomplete details.** Bounded audits are diagnostics, not causal oracles. Repeated placement in one retained curator display did not reacquire a second target and is not accepted behavior. The accepted activation uses one fresh native placement plus exact replay. Reverse ON-to-OFF Zeus entry behavior, client-B/JIP, and ownership migration remain unproven; accepted ACE suspension/resume already owns the underlying no-resupply lifecycle semantics.
8. **Better native or existing mechanism.** Keep Arma's native module framework

9. **Stable contract and causal proof.** Eden requires a real typed SQM module

10. **Replaceable details.** Function names, priority, internal variables,

11. **Characterization.** Typed Eden dispatch, locality, Sync identity, persistence, aggregate modules, and physical causality are established. One real assigned-curator placement, exact attachment, client/server ownership split, authenticated result, replay rejection, and cleanup are also established. Repeated placement in one open display remains an explicit experiment, not specification.
12. **Tribunal promotion.** Typed-Logic/Object/SQM-Sync generation remains the proven generic Eden fixture. The authenticated RFB/X11 curator driver is product-neutral input machinery, but APS owns module selection, claim semantics, target policy, and assertions. A second real consumer is still required before promoting curator claim semantics.

## False-PASS audit

Calling either handler or `YOSHI_fnc_apsEnableVehicle`/toggle API directly is a
pipeline bypass. Config presence, enabled variables, charge top-up, ACE actions,
notification, or logic deletion do not prove authentic module activation.
Positive proof needs fresh exact module/vehicle/projectile identities and the
accepted physical APS oracle. The negative must independently prove a valid
projectile impacts. An absent forged effect is meaningful only after an exact
request receipt proves the authority boundary was reached.

Do not include anti-drone in this contract: its activation policy is separately
deferred. Do not claim JIP, client-N audience isolation, or ownership migration
from client-a.
